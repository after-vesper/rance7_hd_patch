# タイトル画面 1600×1200 化

## 構成の調査結果

`tagTitle@create` (func 4050) が生成するスプライト:

| 要素 | CG | 位置 | Z |
|---|---|---|---|
| 背景帯 A | 12501 (1600×600) | (0,0) | titleback 系 |
| 背景帯 B | 12502 (1600×600) | (0,0) | titleback 系 |
| 火の粉 (8個) | 12505 (24×24) | 散布 | **11** |
| メイン画像 | 12504 (800×600 RGBA) | (0,0) | **21** |
| エフェクト | 12510〜12539 (800×400, 計30フレーム) | (0,18) | 41 |

`tagEffect@create(12510, 30)` が30コマの稲妻アニメを再生する。
**全30フレームを2x化しないと、半分サイズのコマが左上に表示される**
(当初 12510-12519 のみ2x化して発生した不具合)。
| メニューボタン | テキストスプライト | (242, 410+n*39) | ボタン系 |

`tagTitleBack` は `createPixelOnly(800,600)` の内部バッファに 12501/12502 を
コピー合成する経路で、ここに 800×600 固定値がある (`copyBack` 内の nW/nH 等)。
バッファ寸法を 1600×1200 に書き換える実験は全て黒画面 / `createPixelOnly only`
系エラーで失敗したため、この経路は **800×600 のまま維持** する方針に転換した。

## 2025-10 更新: スクロール復元 (ベイク方式は廃止)

下記のベイク方式では `tagTitleBack` のパノラマスクロールが全面画像の
下に隠れてしまい、タイトル背景が静止画になっていた。ユーザー報告を受けて
本来のスクロールを復元した。

原因特定:

- ベイク済み cg12504 (不透明 1600×1200, Z=21) が
  スクロールパノラマ (Z=2,3) と火の粉 (Z=11) を両方覆い隠していた。
- 火の粉 Z を 11→25 に上げるパッチはドキュメント上のみで、
  実 AIN には未適用だった (デプロイ済み ain の実値は 0xb のまま)。
- `tagTitleBack` の 800×600 バッファ / ラップ境界 1600 / コピー領域は
  全て未パッチのまま残っていた。

復元内容:

| 対象 | 内容 |
|---|---|
| cg12501/12502 | パノラマ 1600×600 → **3200×1200** に2x化 |
| cg12504 | ベイク版を破棄し **オリジナル半透明ヴェール** (800×600 RGBA) を2x化 |
| `tagTitleBack@create` | ピクセルバッファ 800×600 → 1600×1200 |
| `tagTitleBack@moveLeft/moveRight` | ラップ境界 1600 → 3200 |
| `tagTitleBack@copyBack` | コピー領域 800×600 / 境界 1600 → 2倍 |
| `tagTitle@create` | スクロール速度 nSize A:1→2, B:3→6 (px/100ms) |
| `tagTitle@create` | cg12500 ロゴ setPos y 60→120 / 雷エフェクト setPos y 18→36 |

AIN パッチは `tools/ain_adv_patch.py` の `SINGLES20` に集約。

※ 以前失敗した `createPixelOnly(1600,1200)` 実験は、CG が 1600×600 のまま
(コピー元 1600×1200 が CG 高さ 600 を超過) だったことが原因と推測。
CG を 3200×1200 に揃えた今回は整合している。

※ 火の粉 Z はバニラ仕様 (11 = ヴェールの下) に戻した。ベイク下では
不可視だったが、半透明ヴェール越しに見える本来の見た目に復帰。

## 旧方式 (参考): ベイク合成 + 最小 AIN パッチ

スクリプトの 800×600 バッファを触らず、**CG 側で見た目を完成させる**方式。

1. **cg12504 を 1600×1200 にベイク合成**
   - 背景: 12501/12502 (1600×600) を縦に並べて 1600×1200 の空を作る
   - その上に 12504 (ロゴ+枠。800×600→1600×1200 に2x) をアルファ合成
   - さらに 12500 (上部帯 800×316→1600×632) を上部に重ねる
   - 結果: titleback バッファが何を描いても、Z21 の全面画像が正しい見た目を覆う
   - ※ QNT 化でアルファを保持 (PNG→QNT のチャンネル順バグを修正済み)

2. **残りの CG を単純2x化**
   - 12500, 12505 (火の粉 24→48px), 12510〜12539 (エフェクト30フレーム全て)

3. **AIN パッチ (Rance7.ain, 復号キー MT19937 seed 0x5D3E3, init 69069倍)**

   | オフセット | 旧 | 新 | 内容 |
   |---|---|---|---|
   | 0x1ff57a | 11 | 25 | 火の粉スプライトの Z。ベイク画像(21)より上に出す |
   | 0x1ff6a0 | 242 | 484 | メニューボタン X を2倍化 |
   | 0x1ff6aa | 410 | 820 | メニュー開始 Y を2倍化 |
   | 0x1ff6f6/0x1ff728/0x1ff75a | 39 | 78 | ボタン縦間隔を2倍化 |
   | 0x19a6aa | 18 | 36 | `tagSelectCg@createSpTitle` の `sact_text_metrics_t` フィールド3 (テキストサイズ)。ボタン文字を2倍化 |
   | 0x199d7c | 322 | 644 | `tagSelectCg@create` のボタン背景スプライト幅 nW |
   | 0x199d8e | 32 | 64 | 同 高さ nH |
   | 0x199e7e/84, 0x199f92/98, 0x19a0a6/ac | 3 | 6 | copyCg 転送先 (3,3)→(6,6) ×3コマ分 |
   | 0x199ea4/aa, 0x199fb8/be, 0x19a0cc/d2 | 316/26 | 632/52 | copyCg 転送元サイズ ×3コマ分 |

   追加 (冒頭画面, ShowWarningScreen / ShowAliceLogo):

   | オフセット | 旧 | 新 | 内容 |
   |---|---|---|---|
   | 0x213efc / 0x213f02 | 800/94 | 1600/188 | 初回起動のみ作られる黒マスク `createPixelOnly` (SP_SET_POSは物理座標のままなので寸法と位置を両方2倍化) |
   | 0x213f20 / 0x213f26 | 800/94 | 1600/188 | 同 `CG_FILL` 塗り潰し範囲 |
   | 0x213f50 | 506 | 1012 | 同 マスク配置Y (`SP_SET_POS` は物理座標) |
   | 0x2142d0 / 0x2142d6 | 800/600 | 1600/1200 | `ShowAliceLogo` 終了時の白フラッシュ `createPixelOnly` |
   | 0x2142f4 / 0x2142fa | 800/600 | 1600/1200 | 同 `CG_FILL` |

   ※ 初回起動 (SaveData なし= `ＯＰ見た` 未設定) のときだけ
   `useMask` が立ち、y506-600 を覆う黒マスクが作られる。
   800×94 のままだと物理座標そのまま左上に出て、
   フェード中に文字が欠けて見える不具合だった。
   ※ SaveData なし時はタイトル前にOPムービーが差し込まれる
   挙動差もある (正常仕様)。

   ボタン背景は CG **10058** (948×26 = 316×26 の3コマ横並び) から
   `createSpriteFromCg` で切り出したもの。これも2x化が必要。

   メニュー描画・ヒットボックスは同じ座標値から作られるため、
   2倍化で枠画像 (cg12504 内のボタン枠) にぴったり収まる。

## 検証結果

- タイトル背景・ロゴが 1600×1200 全面に正しく表示
- 火の粉エフェクトは画面全域に維持 (元々全域だったものを温存)
- メニュー項目がベイク済み枠の中央に配置
- 冒頭シーケンス (注意文→アリスロゴ→MangaGamerロゴ→タイトル) 正常遷移
- 合成クリックの注入が環境上不可のため、ボタンの実クリック確認は手動検証待ち
