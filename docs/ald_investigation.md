## ALD フォーマット (実測 + GARbro ArcALD.cs と一致)

```
[先頭] 3バイトLE のブロックオフセット表 (先頭3バイトは表自体の長さ/256)
       各エントリ = ファイル先頭オフセット >> 8 (256バイト単位)
[各ファイル] u32 header_size / u32 data_size / ヘッダ残り + ファイル名(CP932)
             / データ本体 (256バイト境界に配置)
[末尾16バイト] マジック "NL\x01\x00" (= u32 0x00014C4E、または 0x00012020)
               u32 0x10 / オフセット+9 の u16 がファイル数 / 残りは0パディング
```

## QNT フォーマット (ver 2, 検証済み)

```
u32 'QNT\0' / u32 version(2) / u32 header_size(=0x44)
u32 x, y (描画オフセット) / u32 w, h / u32 bpp
u32 ? / u32 rgb_zlib_size / u32 alpha_zlib_size / (残りヘッダ)
[header_size〜] zlib圧縮 RGB ストリーム → 続いて zlib圧縮アルファストリーム
```

デコード手順 (GARbro ImageQNT.cs 準拠、Python で再現確認済み):

1. RGB ストリームを zlib 展開 (サイズ = 偶数補正後 w*h*3)
2. **チャンネル分離 + 2行インターリーブ**で展開:
   チャンネル(B,G,R)ごとに、(行ペア, 各x) 順に「上行画素, 下行画素」が連続格納
3. アルファは別ストリーム (w*h、行ごとに奇数幅パディング)
4. **差分復号** (出力バッファ上で):
   - 先頭行: 右から `out[i] = out[i-bpp] - out[i]`
   - 2行目以降: 各画素 `out = ((上 + 左) >> 1) - out` (先頭画素のみ `上 - out`)

検証結果: cg04501.QNT (800x600, bpp=24+alpha) を PNG 化して正常な
立ち絵画像が得られた (アルファチャンネル含む)。

## 差分アーカイブ方式の根拠 (ALDLoader.dll 逆アセンブル)

DLL/ALDLoader.dll 内のファイル名パターン:

```
%sB%c.ALD  %sR%c.ALD  %sD%c.ALD  %sW%c.ALD  %sG%c.ALD
%cBGM.ALD  %cRES.ALD  %cDATA.ALD %cWAVE.ALD %cCG.ALD
```

- `%s` = ゲーム名 (Rance7), カテゴリ文字 (B=BGM, W=WAVE, G=CG?), `%c` = 'A'+i
- 実コードで `FindFirstFile("ACG.ALD")` 後、サフィックスを 'A','B','C'… と
  インクリメントしながら各 `{Game}{Cat}{Letter}.ald` の存在を列挙している
- → `Rance7GZ.ald` のような新規サフィックスで追加 .ald を置くだけで
  ゲームが読み込む可能性が高い (公式パッチも同仕組みのはず)
- **同名ファイルの優先順位 (後勝ち/先勝ち) は未確認 → 実機検証が必要**

## 追記 (2026-10-05): リンクテーブル解析と再パック検証

libsys4 `src/ald.c` の解析により、ALD 先頭テーブルは実は2段構造:

- **ポインタテーブル**: エントリ0=テーブル自身のセクタ数、以降は
  各ファイルの先頭オフセット + 終端エントリ
- **リンクテーブル (ファイルマップ)**: ファイル番号(ファイル名の数値部分)で
  インデックスされ `(disk番号+1, そのdiskのポインタindex+1)` を保持。
  **disk番号 = アーカイブサフィックス文字の index (A=0, ..., M=12, Z=25)**
- GA/GM のマップは同一内容 (全CGのマスターマップ) で、fileno 4501-4600 は
  disk0 (GA)、その他は disk12 (GM) を指していた
- フッタ byte8 = 自身の disk 番号+1 (GA=1, GM=13, BA/WA=1) と一致を確認

### 結論

**追加アーカイブ (.ald) 方式は不可。** エンジンが開くのは固定セット
(GA + GM) のみで、追加ボリュームは列挙・オープンすらされない。
リンクテーブルの ptr 値も画像参照には使われない (名前ベース検索と推定)。

**採用方式: 原本 .ald のローカル再パック置換。**

- ツールが原本を読み、差し替え対象のペイロードだけ入れ替えて再パック
- ポインタ表・リンクテーブル・フッタを原本形式通り再生成
  (GA はバイト完全一致を確認済み)
- 原本は .bak 等にバックアップしてから差し替え
- 差し替え画像は「ユーザーが自分でアップスケールした QNT」
- GM は約756MBだがローカル処理なので許容範囲

### 方針転換

- **全アセットを一律 N 倍でアップスケール + Phase 1 側で実寸描画系を ÷N 補正**
  する設計が本命。アセット側での区別は不可能なため。
- Phase 1 側タスク: 「画像サイズから転送矩形を決める」描画パスを特定し
  dest_rect = img_size / N に補正するパッチを設計。

### リンクテーブルの名前空間 (追記5 - 2026-10-13)

ALD リンクテーブルの行は**アーカイブごとの独立した名前空間**:

- `Rance7WA.ald`: SE/音声ファイル番号 → 同アーカイブ内 ptr
- `Rance7BA.ald`: BGM 番号 → 同アーカイブ内 ptr
- `Rance7GM/GA`: CG ファイル番号 (実用上は未使用 - CG は名前解決。
  cg64999 の行が空でもロゴが正常表示されることで実証)

disk 値はアーカイブ末尾サフィックス文字由来 (GA/BA/WA=0, GM=12)。
あるアーカイブのリンク行を別アーカイブのマップで書き換えると
ファイル番号の衝突で壊れる (WA/BA に CG リダイレクトを書いたら
SE/BGM が全てズレて Music_Prepare 失敗した - installer bug, 修正済み)。
